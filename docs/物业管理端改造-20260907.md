# 物业管理端改造

## 真机反馈后的视觉恢复

用户要求以改造前线上样式为准。已恢复 `a37e5fc` 的管理端基础样式（整段原样保留），撤掉首轮扁平化覆盖：原渐变、阴影、字体、胶囊页签、房屋格子与单元卡恢复；新增收据/草稿/报修详情继承同一套样式。底部操作保留，但按钮不再贴边拉成方条。欠费汇总卡移出吸顶区，避免占据长列表空间。

本轮仅修改小程序展示、样式及回归测试，不改后端接口、账单或支付逻辑。收据共用模板、跨页全选、部分发布等功能保留。下文为首轮功能记录；视觉取舍以本节及用户最新要求为准。

验证边界：基础样式逐字节哈希对照旧版；247 项 Node 回归通过；微信编译器检查 44 个 WXML、46 个 WXSS 通过；本轮小程序指纹为 `e614874`。开发者工具 CLI 服务端口仍关闭，没有据此宣称完成模拟器或真机验收。更新分支后请清缓存编译并在真机重新确认。

## 实现范围

- 管理首页：五个页签常驻；楼栋可搜索选择；按单元显示住宅，支持楼层定位；车库、门市分页。切换页签保留位置，返回时刷新数据但不清空列表。
- 欠费：房号/业主/手机号搜索、逾期筛选、20 户分页；全选覆盖当前匹配的全部页，支持取消单户；底部全选、清空及发送入口常驻。发送沿用原业务接口，单次 500 户上限不变。
- 待发布：完整读取批次，进入独立账单明细；全选、部分取消、合计金额、发布确认。未选账单保留草稿。数量区分户数与账单笔数。
- 收款收据：功能页、房屋档案、线下收款完成页新增入口；按日期、渠道、状态及编号/房号查询；汇总取筛选全集，作废记录不计入有效实收。
- 收据内容：业主与管理端共用 `utils/receipt-page.js`、原 WXML 与绘图逻辑；管理端通过租户校验接口取得相同不可变快照。原收据格式、保存到相册和作废行为保留。管理页面本身不开放分享。
- 报修：分页状态列表、独立详情、照片预览、电话、处理人及办结回复；主操作固定底部。
- 房屋与功能详情：共用暖白/深梅色/金色样式；账单分页、收据入口、固定保存/出账/收款/发布操作。清理原型话术、教学型备注，保留必要的业务字段、错误和确认。

## 接口与兼容性

- 新增 `GET /admin/payments/:orderNo/receipt`：明确租户限定，复用业主收据呈现与历史回退规则。
- 收款查询增加 `houseId`，包含合并支付的房屋匹配；分页增加唯一排序键。
- 新增 `POST /admin/bill-batches/:id/publish-selected`：必须提交选中账单 ID、核对总额和幂等键。事务内校验账单归属、草稿状态、金额；原子更新选中账单、审计及通知。剩余草稿不发布，最后一笔发布后批次完成。
- 独立部分发布路径保证旧后端拒绝新请求，而不会忽略新字段后整批发布。
- 欠费接口新增可选页码，默认原首批行为不变，全量汇总不受分页影响。
- 新增租户隔离的报修详情接口。
- 不涉及数据库结构变更、支付回调、计费规则调整；未执行生产写入或部署。
